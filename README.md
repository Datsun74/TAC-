# Сімейні покупки

Спільний закритий список покупок для родини. Кожна сім’я має власний простір: учасники бачать лише свої записи.

## Що вже вміє застосунок

- Вхід без пароля за одноразовим кодом з email.
- Створення власної сім’ї або приєднання до неї за кодом-запрошенням.
- Додавання покупок із категорією, відділом магазину, кількістю та особливостями.
- Режим «Я йду в магазин» із групуванням за категоріями й відділами.
- Позначки «Куплено» та «Відхилено», а також окремі сторінки з їх історією.
- Категорії: «Продукти», «Косметика», «Будівництво», «Сергій особисте» та «Інше».

## Як користуватися

1. Відкрийте [http://localhost:3000](http://localhost:3000) і введіть свій email.
2. Відкрийте найновіший лист від «Сімейні покупки», скопіюйте одноразовий код і введіть його на сторінці входу.
3. Якщо це перший вхід, створіть сімейний простір. Щоб додати родича, відкрийте «Моя сім’я», створіть код і передайте його родичу.
4. У розділі «Додати» створіть покупку.
5. У «Я йду в магазин» позначайте придбане або відхиляйте неактуальні позиції.

## Запуск на своєму комп’ютері

1. Відкрийте папку проєкту в WebStorm та відкрийте **Terminal** у нижній панелі.
2. Встановіть залежності:

   ```powershell
   npm.cmd install
   ```

3. Створіть у корені проєкту файл `.env.local`, скопіювавши `.env.example`, і внесіть дані Supabase:

   ```env
   NEXT_PUBLIC_SUPABASE_URL=...
   NEXT_PUBLIC_SUPABASE_ANON_KEY=...
   NEXT_PUBLIC_TEST_MODE=false
   ```

4. Запустіть застосунок:

   ```powershell
   npm.cmd run dev
   ```

5. Відкрийте [http://localhost:3000](http://localhost:3000).

Якщо PowerShell не дозволяє виконати `npm`, завжди використовуйте `npm.cmd`, як у прикладах вище.

## Налаштування Supabase для нового проєкту

1. У [Supabase Dashboard](https://supabase.com/dashboard) створіть проєкт і внесіть його **Project URL** та **Publishable key** у `.env.local`.
2. У **SQL Editor** послідовно виконайте:
   - `supabase/schema.sql`;
   - `supabase/family-access.sql`;
   - `supabase/family-spaces-and-rejected.sql`;
   - `supabase/add-serhii-personal-category.sql`.
3. У **Authentication → URL Configuration** вкажіть `http://localhost:3000` як Site URL і додайте `http://localhost:3000/auth/confirm` до Redirect URLs.

Не надсилайте файл `.env.local` іншим людям і не додавайте його до Git.

## Важливо про листи для входу

Вбудований поштовий сервіс Supabase призначений лише для перевірки: він надсилає максимум **2 листи на годину на весь проєкт** і в тестовому режимі працює лише з email учасників команди Supabase. Для родини та опублікованого сайту потрібно підключити власний SMTP-сервіс. У цьому проєкті вхід працює через одноразовий код з листа: такий код не може бути використаний поштовим захисним фільтром замість користувача.
