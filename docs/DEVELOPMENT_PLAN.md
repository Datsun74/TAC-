# План розробки «Лист сімейних побажань»

Цей файл — єдине місце, де зафіксовано стан розробки. Ми рухаємося лише одним блоком за раз.

## Правила роботи

1. Для нового блоку готується окремий промт і виконується в окремому чаті.
2. Після виконання ви перевіряєте результат у браузері та повідомляєте про правки або підтверджуєте приймання.
3. Якщо потрібні правки, вони виконуються в межах того самого блоку.
4. Лише після вашого підтвердження створюється Git-коміт.
5. Після успішного коміту статус блоку в цьому файлі змінюється на `✅ Виконано`.
6. Тільки після цього надається промт для наступного блоку. Ми не переходимо до нього автоматично.

## Статуси

- `✅ Виконано` — перевірено та закріплено комітом.
- `🟡 Поточний` — блок, над яким зараз працюємо.
- `⬜ Заплановано` — ще не починали.
- `⏸ Потребує рішення` — потрібен ваш вибір до початку робіт.

## Блок 2 — Модель даних у Supabase

**Статус:** ✅ Виконано

### Мета

Підготувати безпечну структуру даних для покупок і побажань у Supabase.

### Обсяг

- Узгодити поля запису: назва, тип, основна категорія, відділ магазину, кількість, особливості, хто замовив, дата створення, статус, хто купив і дата купівлі.
- Додати SQL-файл зі схемою до репозиторію, щоб структура бази була відтворюваною.
- Створити таблиці в Supabase Cloud через SQL Editor.
- Увімкнути Row Level Security (RLS).
- Додати лише безпечні політики, які не відкривають сімейні дані всім відвідувачам.

### Важливе обмеження

Без механізму ідентифікації користувача не можна безпечно надавати анонімним відвідувачам доступ до приватного сімейного списку. Тому в цьому блоці ми створюємо схему та захист, але не робимо публічний запис або читання сімейних даних із браузера.

### Критерії приймання

- [x] Схема застосована у Supabase Cloud.
- [x] SQL-файл збережений у проєкті.
- [x] RLS увімкнено.
- [x] Політики не відкривають дані публічно.
- [x] Створено Git-коміт блоку 2.

## Блок 3 — Спільний безпечний доступ сім’ї

**Статус:** ✅ Виконано

### Мета

Обрати й реалізувати спосіб, яким члени сім’ї отримуватимуть доступ лише до свого списку.

### Прийняте рішення

- Вхід за одноразовим посиланням на email (Magic Link), без пароля.
- Email використовується лише для входу і не показується в інтерфейсі покупок.
- Кожен член родини має видиме ім’я, наприклад «Сергій»; саме це ім’я показується в полях «Хто замовив» і «Хто купив».
