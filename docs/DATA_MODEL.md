# Модель даних покупок

Цей документ фіксує узгоджену структуру одного запису для майбутніх екранів «Покупки», «Я йду в магазин» і «Куплено».

## Поля запису

| Поле | Призначення |
| --- | --- |
| Назва | Що потрібно придбати. |
| Тип | Завжди `Покупка`; вибір типу в інтерфейсі не потрібен. |
| Основна категорія | `Продукти`, `Косметика`, `Будівництво`, `Сергій особисте` або `Інше`. |
| Відділ магазину | Детальніше групування всередині категорії, наприклад `Молочні продукти`, `Алкоголь` або `ЗОЖ-товари`. |
| Кількість | Текстове значення, наприклад `2 упаковки` або `1 кг`. |
| Особливості | Важливі деталі товару: бренд, розмір, смак тощо. |
| Хто замовив | Ім’я члена родини, який попросив додати позицію. |
| Дата створення | Автоматично фіксується під час створення запису. |
| Статус | `Активна` або `Куплено`. |
| Хто купив | Обов’язково вказується під час позначення позиції купленою. |
| Дата купівлі | Автоматично фіксується разом зі статусом `Куплено`. |

## Майбутній сценарій покупки

1. У «Я йду в магазин» людина бачить лише активні покупки, згруповані за основною категорією і відділом магазину.
2. Позначка «Куплено» збереже ім’я покупця й дату купівлі, після чого позиція зникне з активного списку.
3. У «Куплено» зберігатиметься історія придбаних позицій. Якщо куплено всі активні позиції, розділ магазину покаже порожній стан і лічильник `0`.

Робоча позначка «Куплено», форми й екрани з реальними даними будуть створені у наступних блоках після налаштування безпечного доступу родини.

## Імена та приватність

Для входу кожен член родини використовуватиме власний email через одноразове посилання, без пароля. Email не зберігатиметься у записі покупки й не показуватиметься в інтерфейсі. Натомість для історії та списків використовуватиметься видиме ім’я, наприклад `Сергій`.
